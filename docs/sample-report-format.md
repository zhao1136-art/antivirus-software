# 样本分析报告格式（参照卡饭 bbs.kafan.cn/thread-2295665 的写法）

> 来源样本：`doc-kafan.exe`（腾讯 JDK 白加黑远控）
> 这份文档记录**那个帖子的报告结构**，作为我们产品输出样本报告的模板。
> 2026-10-17 从原文提取，字段与约定都照抄，不自行发挥。

## 一、整体结构（8 段，按此顺序）

```
1. 文件指纹        ← 每个文件的 5 种哈希 + 归属判定
2. 查杀结果        ← 各家引擎的扫描结论（含版本/病毒库时间）
3. 文件目录        <- 树形，每项带指纹简写与说明
4. 文件属性        ← PE 元数据（编译器/调试符号/时间/版本/数签）
5. 运行链          ← A＞B＞C 全角箭头描述的调用链
6. 参考数据        ← 配置样本（脱敏）
7. C2 / IOC        ← 域名/IP，一律 [.] 转义
8. 参考解析        ← DNS/HTTP 响应样本
```

## 二、约定（这是格式里最值得抄的部分）

### ① 指纹用 5 种，不只一种

```
文件名（判定）
大小: <字节> 字节 : <KiB> KiB
CRC32: <8 位大写 hex>
XXH64: <16 位大写 hex>
SHA256: <64 位小写 hex>
SHA3-256: <64 位小写 hex>
```

- **CRC32/XXH64 大写，SHA256/SHA3-256 小写** —— 保持原样，不要统一大小写
- 大小写两种写法**同时给出**：`209456 字节 : 204 KiB`

### ② 每个文件必须**标注归属**

原文里每个文件名后面跟一个判定括号：

```
javaw.exe（官方文件）
rt.jar（恶意加载）
currency.data（ShellCode）
jvm.cfg（正常文件）
```

**这个标注是整份报告的核心** —— 它把"白加黑"讲清楚了：
哪些是正版被利用的、哪些才是真恶意。没有这一列，读者无法理解为什么
一个带腾讯数签的 exe 会是恶意的。

### ③ 域名/IP 一律 `[.]` 转义

```
http://ce[.]oa[.]com/bia?id=a52dc98ea36f781e
141[.]144[.]196[.]217
205[.]251[.]193[.]172
```

**目的**：读者点不开，避免误触。报告里**不出现可直接点击的活链接**。

### ④ 运行链用全角 `＞` 串起来

```
资源管理器＞cache＼bin＼javaw.exe
javaw.exe＞jli.dll＞自定义运行环境为＞cache＼jre＼bin
javaw.exe＞msvcr100.dll＞shellcode
shellcode＞cache＼jre＼lib＼currency.data＞解密配置
currency.data＞解密成功＞javaw.exe＞子进程
```

路径用**全角 `＼`**（`＼` 而非 `\`）—— 同样是为了不可直接复制成可执行路径。

### ⑤ 参考数据用**脱敏占位值**

```json
{
  "user": "administrator",
  "host": "示例主机名",          ← 明确写"示例"，不写真实值
  "ip_priv": "1.1.1.1",
  "mac": "00:01:02:03:04:05",   ← 保留格式，值是假的
  "pid": 1234
}
```

**真值 + 假值混合**：结构是真的（这样能看出 C2 协议怎么设计的），
值里凡是能定位到真实主机的都换成占位。

### ⑥ 目录树里用 `＃` 注释

```
钓鱼文档
　　├── 1.lnk　＃窗口最小化，指向（C:\Windows\explorer.exe cache\1.pdf）
　　└── cache　＃Ｈ隐藏／Ｓ系统
　　　　├── jli.dll　＃5006734C．腾讯数签９４
　　　　└── javaw.exe　＃16E1A182，腾讯数签６ｅ
```

- 用**全角空格**（`　`）做缩进，`├──`/`└──` 画树
- 每个文件后跟 `＃` + **CRC32 前 8 位** + 一句说明
- **数签有效期/签名方**用简写：`腾讯数签９４`（= 腾讯签名，序列号末尾 94）
- 目录属性用**全角字母**：`Ｈ隐藏／Ｓ系统`

## 三、查杀结果怎么写

```
<引擎>扫描（我自己的本地扫描结果）
<版本号> 版本
<月-日 时:分> 病毒库

<YYYY/MM/DD HH:MM:SS>
病毒防护
病毒查杀
自定义扫描(手动执行)，发现 N 个风险项目

病毒库时间：...
开始时间：...
执行类型：手动执行
扫描类型：自定义扫描
总计用时：00:00:03
扫描对象：433
扫描文件：40
发现风险：0
已处理风险：0
```

**必须写清**：引擎版本、病毒库时间、扫描类型、对象数/文件数、
发现/已处理 —— 尤其是**病毒库时间**，否则"没报"可能是病毒库太旧。

## 四、我们目前**做不出来的**（要诚实标注）

| 帖子有的 | 我们的状态 |
|---|---|
| **CRC32 / XXH64 / SHA3-256** | ✗ 病毒库只支持 md5/sha1/sha256 |
| PE 数签链、证书序列号 | ✗ 需要 WinVerifyTrust + 证书解析，未做 |
| 调试符号 / 编译时间 / 文件版本 | ✗ 需要解析 PE 资源 + CodeView，未做 |
| 侧载调用链（javaw→jli.dll→jre） | ✗ 无同目录载荷关联分析 |
| shellcode → currency.data 解密 | ✗ JAR/shellcode 无规则覆盖 |
| C2 域名 / 参考数据 | ✗ 未提取；但 YARA 可以按字符串匹配写 |

## 五、可立即照做的部分

1. **指纹表**：我们能算 MD5/SHA1/SHA256 + 大小 → 5 种里能出 3 种
2. **归属标注**：能出（来源是 YARA 规则名 / 签名库 / 启发式）
3. **文件目录树**：解包后能出
4. **C2 转义**：这是**排版约定**，不是能力，照做即可
5. **运行链**：结构能出（我们已记录父进程/子进程），但链路深度不如原文
