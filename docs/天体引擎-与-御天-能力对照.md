# 天体引擎 × 御天 · 能力与短板对照

> 测量时间：2026-10-31
> 测量方式：两个项目用**同一套脚本**统计（同一 `os.walk`、排除 `__pycache__/libs/build/dist`），
> 测试均**实际执行**过，不是照抄自述。
>
> - 御天：`H:\Caelire`（backend + ui_tk）
> - 天体引擎：`G:\天体引擎`（tianti 内核）

---

## 0. 一句话结论

**两个项目不重复、不竞争，是互补关系；但工程成熟度差一个量级。**

御天 = **静态检测的广度**（特征库 / YARA / ML / 云查 / 情报），但架构臃肿、测试近乎为零。
天体 = **动态行为的深度**（沙箱执行 / capa 兼容规则 / 行为检测器），工程纪律明显更好，但能力面窄、且受"没有 VM 隔离"硬约束。

**最关键的互补点**：御天今天暴露的"闸门二对 PE 样本无法满足"，正好是天体能力覆盖的地方。

## 5. 互补性分析（本文档的重点）

### 5.1 御天今天暴露的具体缺口

修"查出来什么都不做"时定位到：**闸门二要求 YARA 之外再有引擎点头，而确认引擎只有 `hash` 和 `heuristic`**：

- `hash` 需要样本哈希精确在库（238,537 条）—— 新样本通常不在
- `heuristic` 的 PE 分路上限 70 分，**需"异常 PE 头 + 体积<10KB + 双扩展名"三项全中**才够 60 门槛

→ **对 PE 样本，闸门二实际只剩"哈希在库里"一条路**；不在库就永远"仅告警"。

### 5.2 天体正好补这个位置

天体输出的是 `clean / suspicious / malicious` + 置信度 + 证据链，来源是**沙箱执行**，
与 YARA（静态模式匹配）、hash（精确比对）、heuristic（静态启发）**完全正交**。

把它作为御天闸门二的**确认引擎**，比继续调启发式阈值合理：
- 正交性远好于"哈希 + 启发式"
- 有证据链，可解释
- 天然解决 PE 样本的确认问题

**但前提**：天体必须先有 VM 隔离。否则拿它跑真样本 = 在本机执行恶意代码，而御天恰恰是要保护这台机器。

### 5.3 三种整合方案对比

| 方案 | 做法 | 优点 | 代价/风险 |
|---|---|---|---|
| **A. 进程内嵌入** | 把 `tianti` 包作为御天的依赖，闸门二里调 `tianti.replay`/`scan` | 最快见效；无 IPC | 耦合紧；沙箱要真跑就得有隔离；`tianti` 是 3.12 目标而御天打包用 3.14 |
| **B. 子进程 / 本地 API** | 御天按需拉起 `tianti.exe`（或 `tianti serve`），走 HTTP/JSON | 隔离干净；可单独升级；崩溃不拖垮御天 | 需要进程管理与超时；首样本约 3.4s |
| **C. 只借鉴行为模型** | 不接引擎，把天体的 26 条检测器/评分语义移植进御天 ETW 路径 | 无新依赖 | 丢掉了"真执行"的核心价值；ETW 限流仍在 |
| **D. 先不动，各自独立** | 保持现状 | 零风险 | 缺口仍在（PE 样本确认不了） |

**建议：B**。理由：
- 天体的价值就在"真执行"，进程内嵌没法隔离失败；
- 御天的 `LocalScanner` 已经有"起子进程扫描"的模式（`native_engine.exe`），加一个引擎成本可控；
- `tianti.spec` 已经产出 `tianti.exe`（2.6 MB），可以直接用。

**但顺序必须是**：天体先补 VM/emulation → 再接御天。否则等于把"在本机执行恶意样本"变成默认路径。

## 6. 结论与建议

### 御天该从天体学什么

1. **测试纪律**：从 1.3% 提到哪怕 10%，先把"检测→处置"主链路（local_scanner / signature_manager / quarantine / response_center）覆盖
2. **异常处理收紧**：843 处 `except Exception` 里，扫描链路的必须进日志与扫描报告
3. **发布纪律**：天体有 v0.3.0/0.3.1/0.3.2 三个 tag 与 RELEASE 报告，御天只有版本号
4. **文档诚实度**：天体的"已知限制"是真的限制；御天部分注释与实现不符（本会话已发现多处）

### 天体该从御天学什么

1. **产品面**：实时防护、云查、情报源、签名校验（真证书链）—— 这些是"能用"的必需品
2. **签名校验**：御天已实现内嵌 + 目录签名，天体还是占位
3. **情报源接入**：御天的 maltrail 106 万域名对样本研判有用

### 不要做的事

- **不要把御天的 `app.py` 东西搬进天体** —— 那 843 处宽泛异常会把天体的测试价值吃掉
- **不要在天体没 VM 隔离前让它跑真实恶意样本**
