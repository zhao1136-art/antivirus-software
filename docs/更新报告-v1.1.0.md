## 给非技术用户的三句话

**这次更新把界面整个换了，现在是独立窗口，不再借浏览器打开，看着更像一款正常的软件。**
**更重要的是它变得"谨慎"了 —— 以前只要一条规则说有威胁就自动把文件搬进隔离区，现在必须两个不同引擎都同意才动手，宁可漏一点，也不误删你的文件。**
**另外它认识的可疑网站和地址多了一百多万条，但机器学习那部分仍然是"仅供参考"，不会自己下结论。**

---

## 一句话概括

**界面换成了原生 Tkinter，检测侧重点从"多检出"转向"少误杀"** ——
加了跨引擎闸门、把误报率 48% 的 ML 降级为参考、情报库扩容到百万级；
同时补了取证工具、安全审查修复，并新增了一份**不随发布包分发**的内核驱动实验源码。

## 一、重点更新

### 1. 全新桌面界面（Tkinter，14 个页面）

主程序不再依赖 WebView2 和浏览器，改为原生 Tkinter：

- `ui_tk/` 整体入库：26 个文件 / 395 KB，`run_ui.py` + `andun_ui/` + 14 个页面
- 新增两个此前没有入口的页面：
  - **隐私防护页** —— 隐私痕迹扫描/清理、受保护敏感文件增删、访问记录
  - **名单管理页** —— 文件白名单（按路径/按哈希信任）、进程黑白名单增删
- 补回两处换界面后丢失的入口：**实时防护 CPU 节流**（低 5%/中 10%/高 15%）、**退出程序**
- 无窗口自检：`python run_ui.py --self-test`（14 页构建 + 定时器释放）
- 删除注入到 `frontend/*.html` 的网页威胁弹窗 —— 主程序用户已看不到它，
  决策通道改为「界面内待决列表」+「桌面置顶窗口」两条

### 2. 误报治理（本期最实质的变化）

| 措施 | 效果 |
|---|---|
| **双层阻拦**：YARA 命中后必须至少一个其他引擎也命中才允许隔离 | 单引擎命中不再能直接搬走文件 |
| **ML 降级**：实测对 936 个合法系统文件误报率 **48%**，撤掉处置权 | ML 的 action 固定为 `alert`，只作参考 |
| **组合信号加权评分**：多信号加权，只评分不处置 | 给处置层提供可解释的依据 |
| **误报反馈闭环**：隔离区「这是误报」按钮 + 上报接口 + 汇总工具 | 用户反馈能回流到规则复核 |

> 背景：2026-10-03 一条规则（`EXE_in_LNK`）在 514/585 个合法 System32 文件上命中，
> 导致 42 个系统文件被搬走。现处置流程为四道闸门（规则鉴别力 → 可信文件 → 跨引擎确认 → 用户决定）。
> **还有一处隐性问题被修掉**：原"闸门二"存在自我确认漏洞 —— 同一引擎既提供命中又提供确认。

### 3. 威胁情报库扩容

| 情报源 | 规模 |
|---|---|
| **maltrail** | **106 万恶意域名 + 2.3 万 IP** |
| **IPsum**（公有领域） | IP 信誉 |
| **abuse.ch Feodo** | 僵尸网络 C2 |
| 原有 ESET / Blocklist.de | 保留 |

配套：`tools/import_feeds.py`、`tools/build_ioc_index.py`；
IOC 哈希从 32 位有效熵升级到 **blake2b-64**（含国内镜像回退）；
第三方许可合规补齐（GPL-2.0 / Apache-2.0 / 第三方许可清单）。

### 4. 机器学习

- **自训练 PE 模型落地**：ONNX + LightGBM 两套产物，`features.json` 作为特征契约
- 在 4910 个本地样本上 holdout **AUC 0.9997 / 误报率 0.13%**
- 但**刻意不给处置权** —— 数据来自本机、规模有限、泛化能力未经验证
- 修掉一个静默 bug：ML 检出因返回字典缺 `verdict` 键而被丢弃
- 重训时排除了训练缓存，修掉良性集里混入恶意样本的**标签污染**

### 5. 性能

- **PE 特征提取向量化：1.89 → 7.5 MB/s（4.0x）**，特征输出完全等价
- YARA / ML 增加时间预算，避免单文件拖垮扫描

### 6. 取证与分析工具

新增 10 个独立工具，其中对使用者最直接的两个：

- `tools/sample_analyzer.py` / `_gui.py` —— 通用样本分析（哈希 / PE / 启发式 / IOC），**不出网**
- `tools/signal_score.py` —— 组合信号加权评分 + 校准台
- 取证输出含：CRC32 / XXH64 / MD5 / SHA1 / SHA256 / SHA3-256 / BLAKE2b、PE 结构、区段熵、导入表、PDB 路径、IOC

### 7. 安全加固（审查清单 15 项）

- **A 组 8 项**：接口 500、扫描覆盖、打包配置、静默失效
- **B 组 7 项**：配置持久化、闸门二、扫描失败记账、令牌下发、自保护
- 修打包版"无法启动扫描"（日志写入失败导致扫描请求 500）
- 去掉本地令牌，前端直连后端，改为只挡外部网页的跨源请求

### 8. 原生层

- 新增 WDM 驱动**实验性源码**：`backend/driver/andun_driver/`，
  **12 个 `.c` 源文件**（目录共 18 个文件），含
  `object_callback.c` / `process_callback.c` / `registry_callback.c` /
  `file_filter.c` / `network_filter.c` / `self_protect.c` / `rootkit_scan.c`
- **未编译、未签名、不随发布包分发、没有任何默认启用路径**

## 二、升级须知（行为变化）

这几项会改变你实际用到的行为，**升级后如果觉得"怎么不自动处理了"，请先看这里**：

| 变化 | 影响 |
|---|---|
| **单引擎命中不再自动隔离** | YARA 命中后必须再有 hash 或 heuristic 命中，否则只告警 |
| **ML 不再参与处置** | ML 有检出也只显示为参考信息，action 固定 `alert` |
| **网页威胁弹窗已删除** | 决策改在界面「待决威胁」列表或桌面置顶窗口 |
| **本地令牌移除** | 前端直连后端；跨源请求仅拦截外部网页 |
| **`rtguard/` 死副本删除** | 独立实时防护进程仍存在，走正规通道启动 |
| **`logo_splash.py` 删除** | 启动闪屏逻辑移除 |

## 三、已知限制（架构性边界，非待办）

- **没有可用的内核驱动** —— 默认全用户态；绕过 ETW 的手法（直接系统调用等）看不到。
  驱动仅为实验源码，**在实体机加载未签名驱动会蓝屏甚至无法开机**
- **ETW 限流无差别** —— Kernel-File 120 事件/秒、Kernel-Process 150/秒，
  超限连已判定命中的事件也一起丢；解压大包、批量编译时必然触发
- **Threat-Intelligence provider 只对签名杀软开放** —— 未签名构建里 9 条注入类规则不触发
- **`Kernel-File` 只听创建/重命名** —— 看不到写入内容，也看不到删除
- **沙箱不是真 CoW** —— `engine: copy` 只隔离样本及其同目录，样本对 `C:\Windows\...` 的绝对引用照旧打到真实系统
- **WMI 创建进程（T1047）未覆盖**

## 四、部署与打包

- **必须使用 `backend/御天.spec`**。`御天_onedir.spec` 是 2026-10-03 的旧版，
  引用已删除的 bingduku 目录、不含 ui_tk 检查，**构建会失败**
- 打包配置本期已修正：去掉硬编码盘符、改用 `SPECPATH`
- **`御天.spec` 有一处未提交的更正**：pywin32 相关（`pythoncom`/`pywintypes`/`win32com`）
  必须继续排除 —— 本机没装 pywin32，两处使用都有无依赖回退；
  去掉 excludes 反而会让 PyInstaller 的 pywin32 钩子在隔离子进程里崩溃
- ⚠️ **重新打包后需要重新应用"内嵌浏览器"补丁**：`pythonnet\runtime` 与 `webview\lib`
  两个目录要换成 Junction（指向 `%LOCALAPPDATA%\Andun\runtime\exe\`），
  否则内嵌 WebView2 会退回系统浏览器。脚本：`backend/给御天exe打补丁.ps1`
