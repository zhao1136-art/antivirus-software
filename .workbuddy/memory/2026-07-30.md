## F12 紧急处置模块（新增）
用户要求加入应急处置方案：病毒控制电脑时连按F12可关闭所有非系统进程。

### 核心模块 engine/emergency_kill.py（新文件，~310行）
- `EmergencyKillManager` 类：管理热键注册、连按检测、杀进程、日志。
- **热键**：`RegisterHotKey(None, 0, MOD_NOREPEAT, VK_F12)` 注册 F12，线程内 `GetMessageW` 循环等待 `WM_HOTKEY`。
- **连按检测**：2 秒窗口内连按 ≥5 次（TRIGGER_COUNT=5）→ 触发执行，30 秒冷却防重入。
- **进程分类**：`SYSTEM_PROCESSES` 白名单 ~34 个（继承 system_guard 的 12 个 + System/Registry/MemoryCompression/svchost/explorer/ctfmon 等），不杀 PID ≤4（System Idle/System）、不杀安盾自身。
- **杀进程**：`_send_wm_close(pid)` 通过 EnumWindows → GetWindowThreadProcessId 匹配窗口 → PostMessage(WM_CLOSE) → `WaitForSingleObject(handle, 3000)` → `TerminateProcess` 强制结束。
- **日志**：每��触发写入 `data/logs/emergency_kill.log`，记录被杀/跳过的进程名、PID、原因。

## 双进程互保（自保护）
用户要求：防止恶意软件关闭安盾进程。

### 实现方式（app.py 入口内嵌，~90 行）
- **`_run_watchdog_mode()`** — watchdog 模式入口：读取 `--parent-pid` → OpenProcess(SYNCHRONIZE) → WaitForSingleObject 阻塞 → 主进程退出后检查 `%TEMP%\.andun_clean_exit` 文件 → 存在则正常退出、不存在则 Popen 重启主进程。
- **`_start_self_protection()`** — 主进程调用：subprocess.Popen 拉起自身 `--watchdog` → atexit 注册清理（创建 clean_exit 文件 + TerminateProcess 守护） → 守护线程 WaitForSingleObject 监控守护进程，守护被关则自动重启。
- watchdog 分发在 `if __name__ == "__main__":` 最顶部，`--watchdog` 参数跳过所有重型导入（uvicorn/webview/FastAPI 等不加载）。

### 验证结果
- 主进程 (PID 6320) 启动 → 守护进程 (PID 4712) 自动拉起 → 8899 端口正常监听。
- 守护进程在 WaitForSingleObject 中阻塞等待主进程，无崩溃无错误。
- `app.py --watchdog --parent-pid 99999`（无效 PID）→ OpenProcess 失败 → 返回 1 正常退出。
- 正常退出：`atexit` 创建 `.andun_clean_exit` → 杀守护 → 守护检查文件 → 不重启。
- 恶意杀主：无 clean_exit 文件 → 守护 2 秒后 Popen 重启。
